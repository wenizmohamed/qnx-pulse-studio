STEP 01 · HOST ENVIRONMENT

Initialize QNX SDP 8.0 and verify toolchain

Source the QNX SDP 8.0 environment script to expose QNX_HOST, QNX_TARGET, qcc, and mkifs. Confirm gcc_ntox86_64 is listed by qcc -V.

bash (Linux / macOS)
source ~/qnx800/qnxsdp-env.sh
qcc -V
which mkifs qemu-system-x86_64
cmd (Windows)
cmd /c "C:\qnx800\qnxsdp-env.bat && qcc -V && where mkifs"
STEP 02 · TARGET BINARIES

Cross-compile sensor_broker and motor_ctrl with qcc

target-qnx8/src/sensor_broker.c attaches a channel with name_attach(), services synchronous MsgReceive()/MsgReply() requests at SCHED_FIFO priority 55f, sends MsgSendPulse() notifications, and publishes state to /pps/qnx/telemetry. motor_ctrl.c runs a 1 kHz control thread (60f), a medium-priority diagnostic thread (35f), and a low-priority calibration thread (15f).

Makefile (qcc -Vgcc_ntox86_64)
cd target-qnx8
make all
# outputs build/sensor_broker and build/motor_ctrl linked with -lslog2
CMake (qnx8-toolchain.cmake)
cmake -B build -DCMAKE_TOOLCHAIN_FILE=qnx8-toolchain.cmake
cmake --build build
STEP 03 · IMAGE FILESYSTEM

Assemble instrumented x86_64 IFS image with mkifs

qnx8-qemu-x86_64.build bundles procnto-smp-instr (required for kernel event tracing via tracelogger), slogger2, pps, pidin, slog2info, traceprinter, and both compiled binaries.

mkifs (x86_64 multiboot IFS)
cd target-qnx8
mkifs -v qnx8-qemu-x86_64.build build/qnx8-pulse-x86_64.ifs
ls -lh build/qnx8-pulse-x86_64.ifs
STEP 04 · QEMU RUNTIME

Boot QEMU x86_64 and verify pidin and /pps/qnx/telemetry

Boot the IFS with 2 vCPUs and serial stdio, then verify sensor_broker is idle in RECEIVE state at 55f.

host (qemu-system-x86_64)
qemu-system-x86_64 -machine q35 -cpu max -smp 2 -m 512 \
  -kernel target-qnx8/build/qnx8-pulse-x86_64.ifs -nographic -serial mon:stdio
target ksh (verify services)
pidin -F "%a %b %p %J %S %h"
cat /pps/qnx/telemetry
slog2info | tail -n 10
STEP 05 · FAULT REPRODUCTION

Trigger priority inversion and capture target diagnostics

Run motor_ctrl --inject-inversion (initializes g_calib_mtx with PTHREAD_PRIO_NONE) and collect synchronized tracelogger/traceprinter, pidin, slog2info, and /pps output via capture-diag.sh.

target ksh (inject and capture)
/proc/boot/motor_ctrl --inject-inversion --iterations 200 &
/proc/boot/capture-diag.sh /tmp/capture-inversion 3
STEP 06 · HOST ANALYSIS

Analyze capture with qnx-pulse CLI

Run the host CLI against your capture directory (or the bundled samples/brake-ecu-inversion fixture). The analyzer flags the 1390µs inversion window, the 1842.4µs deadline overrun, and exits with status 2 for CI gating.

host (qnx-pulse CLI, exits with status 2)
node cli/qnx-pulse.mjs analyze samples/brake-ecu-inversion --deadline 500
node cli/qnx-pulse.mjs analyze samples/brake-ecu-inversion --deadline 500 --format markdown --out audit-fail.md
Open brake-ecu-inversion.cap in Workbench
STEP 07 · FIX AND VERIFICATION

Switch mutex protocol to PTHREAD_PRIO_INHERIT

Setting PTHREAD_PRIO_INHERIT instructs procnto-smp-instr to boost calib_worker from 15f to 60f while actuator_1khz (60f) waits on g_calib_mtx. Medium-priority diag_streamer (35f) cannot preempt the mutex holder, holding worst-case loop jitter to 112.6µs.

target-qnx8/src/motor_ctrl.c
BEFORE · --inject-inversion (exit 2) max 1842.4µs 
pthread_mutexattr_t mattr;
pthread_mutexattr_init(&mattr);
- pthread_mutexattr_setprotocol(&mattr, PTHREAD_PRIO_NONE);pthread_mutex_init(&g_calib_mtx, &mattr);
pthread_mutexattr_destroy(&mattr);
AFTER · --fixed-pi (exit 0) max 112.6µs

+ pthread_mutexattr_setprotocol(&mattr, PTHREAD_PRIO_INHERIT);pthread_mutex_init(&g_calib_mtx, &mattr);
